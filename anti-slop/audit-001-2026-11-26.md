# SIMPRES UI audit

Scope: public landing page and authenticated layout, based on Blade source and a live desktop view. This is a focused review, not a complete click-through or mobile accessibility test.

## Findings

1. **HIGH — Remove or substantiate absolute security and documentation claims.** `resources/views/welcome.blade.php` displays “Data Aman”, “keamanan data terjamin”, and a fixed “100% Terdokumentasi Resmi” metric. The page does not provide evidence or a source for those claims. Remove them or replace them with verifiable, specific information. Violates R-17, R-36, and R-38.

2. **HIGH — Give the mobile sidebar toggle an accessible name.** The icon-only button in `resources/views/layout/app.blade.php` toggles the sidebar but has no `aria-label` or other text name. Add an accessible name and expose the open/closed state; consider Escape and focus handling while improving the mobile menu. Violates R-32 and R-39.

## Follow-up

Finding 2 was approved and fixed in `resources/views/layout/app.blade.php`: the toggle now has an accessible name, `aria-controls`, and a synchronized `aria-expanded` value. On mobile, the collapsed sidebar is inert; opening it moves focus to the first navigation link, and Escape closes it and restores focus to the toggle.

Verification: Blade views compiled successfully; the Laravel test suite passed (24 tests, 158 assertions). In the live dashboard, the mobile menu behavior was exercised: open updated the label/state and focused the first link; Escape closed it, restored focus, and made the hidden sidebar inert.

Finding 1 remains unchanged and was not approved.
